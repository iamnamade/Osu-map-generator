# Map Validation

## Purpose

Phase 3 adds a dedicated validation and quality-scoring system for browser beatmaps generated by this project.

The validator inspects:

- beatmap JSON
- audio-analysis JSON
- selected difficulty preset

It then reports issues, calculates category scores, calculates an overall score, and exports a readable JSON report.

## Original Implementation

This validation system is original project code.

It does not use:

- official osu! difficulty or star-rating code
- third-party osu! validators
- external ranking repositories
- machine learning
- pretrained models
- remote APIs

The scores describe our own generator-quality metric only.

They are not official osu! ratings, rank approvals, or star values.

## Why This Phase Is Analysis Only

Phase 3 only inspects, measures, scores, reports, compares, and displays diagnostics.

It does not:

- repair beatmaps
- move objects
- snap timestamps
- insert notes
- remove notes
- regenerate candidates

Automatic fixes will be handled in a later phase after we trust the diagnostics.

## Python Version

Use Python 3.10 or newer.

The project includes Windows-friendly Node wrappers that prefer `.venv` when it exists.

## CLI Usage

### Validate One Map

PowerShell:

```powershell
python -m tools.map_generator.cli validate `
  --map public/maps/generated/test-song-normal.json `
  --analysis public/analysis/test-song-analysis.json `
  --difficulty normal `
  --output public/reports/test-song-normal-report.json
```

Add `--verbose` to print every detected issue instead of only the highest-priority five.

### Validate All Generated Maps

PowerShell:

```powershell
python -m tools.map_generator.cli validate-all `
  --maps-dir public/maps/generated `
  --analysis public/analysis/test-song-analysis.json `
  --reports-dir public/reports
```

This command infers difficulty from generator metadata first, then falls back to the filename.

### Compare Existing Reports

PowerShell:

```powershell
python -m tools.map_generator.cli compare-reports `
  --reports-dir public/reports
```

The comparison ranks our generated candidates by overall score and shows category differences from the best report.

## Severity Levels

`info`

- useful context that is not necessarily bad

`warning`

- likely quality problem or readability concern

`error`

- clear issue that should usually be corrected

`critical`

- invalid, unsafe, impossible, or severely unplayable behavior

Critical structural failures also cap the overall score.

## Validation Categories

### Structural

Checks metadata, object shape, unique sequential IDs, timestamps, playfield bounds, start and end padding, audio-duration limits, generator metadata, and non-finite numeric values.

### Timing

Measures every object against nearby beats and onsets, chooses the best anchor, calculates confidence, flags mistimed objects, repeated early or late bias, weak anchors, and silence placements.

### Rhythm

Analyzes consecutive object gaps, percentiles, standard deviation, rapid runs, long empty spaces, isolated speed spikes, dense quiet clusters, and overly mechanical uniform timing.

### Movement

Measures jump distance, time gap, cursor speed, angle, direction change, edge distance, and local movement spikes.

### Readability

Flags exact stacking, tiny jump runs, approach-circle overlap, and circles placed too close to the edges.

### Spatial Balance

Tracks region usage on a 4 by 3 grid, coverage, left and right balance, top and bottom balance, center use, edge use, corner use, and local trapping in small playfield zones.

### Repetition

Detects repeated coordinate pairs, two-point loops, repeated shapes, repeated gap sequences, repeated distance patterns, and repeated angle patterns.

### Density Consistency

Builds fixed windows, compares local map density to audio energy, flags unexplained spikes, sparse high-energy sections, dense low-energy sections, flat density across strong energy changes, and abrupt endings.

### Difficulty Consistency

Compares real map behavior to the selected preset using density, jump distance, speed, timing complexity, and spatial variation ratios.

## Score Categories

Every report exports the following category scores from 0 to 100:

- structural
- timing
- rhythm
- movement
- readability
- spatialBalance
- repetition
- densityConsistency
- difficultyConsistency
- overall

## Overall Score Weights

The current overall weighting is:

- Structural: 15%
- Timing: 20%
- Rhythm: 15%
- Movement: 15%
- Readability: 10%
- Spatial balance: 5%
- Repetition: 5%
- Density consistency: 10%
- Difficulty consistency: 5%

These weights live in `tools/map_generator/validation/quality_scorer.py`.

## Score Interpretation

- 90 to 100: Excellent foundation
- 80 to 89: Strong map with minor issues
- 70 to 79: Playable but needs refinement
- 60 to 69: Noticeable quality problems
- 40 to 59: Major revision required
- 0 to 39: Invalid or severely unplayable

## Report JSON Format

Reports are written as readable UTF-8 JSON with indentation.

Current generated report paths:

- `public/reports/test-song-easy-report.json`
- `public/reports/test-song-normal-report.json`
- `public/reports/test-song-hard-report.json`

The top-level shape is:

```json
{
  "version": 1,
  "map": {},
  "valid": true,
  "playable": true,
  "scores": {},
  "interpretation": "Strong map with minor issues",
  "summary": {},
  "metrics": {},
  "issues": []
}
```

The `metrics` object currently includes structural, timing, rhythm, movement, spatial, density, repetition, and difficulty summaries.

The `issues` array contains stable issue codes plus human-readable context such as object IDs, times, measured values, limits, and suggestions.

## How Audio Analysis Affects Validation

The validator reads the Phase 2 analysis JSON and uses it to:

- find nearest beats
- find nearest onsets
- estimate local anchor confidence
- inspect local RMS energy
- detect quiet windows
- detect high-energy windows
- measure whether density changes are musically supported

The report is only as good as the supplied analysis file, so validate a beatmap against analysis generated from the same audio source.

## Tuning Thresholds

Thresholds are intentionally centralized in code rather than scattered through one giant file.

Common tuning points:

- `tools/map_generator/config.py`
  - movement limits
  - gap targets
  - circle size
  - approach time
  - quiet and high-energy thresholds
- `tools/map_generator/validation/timing_validator.py`
  - anchor tolerances
  - confidence rules
- `tools/map_generator/validation/rhythm_validator.py`
  - rapid-run and long-gap logic
- `tools/map_generator/validation/movement_validator.py`
  - overlap, speed, and spatial heuristics
- `tools/map_generator/validation/quality_scorer.py`
  - score weights
  - issue penalties
  - metric penalties

## Known Limitations

- circles only
- no official osu! star rating
- no section-aware music theory model
- no slider or spinner validation
- some heuristics are intentionally conservative and may over-report on tiny test maps
- report comparisons are meaningful within this project, not across unrelated games or mapping systems

## Frontend Integration

The Phaser start screen loads the matching report JSON for generated maps and shows:

- overall score
- interpretation
- category scores
- issue counts
- highest-priority issues

If a report is missing or malformed, the UI shows a readable message and gameplay still loads.
